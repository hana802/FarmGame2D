# FarmGame2D 게임 기획 개요

## 프로젝트 방향

FarmGame2D는 스타듀 밸리처럼 하루를 보내며 농장을 성장시키는 탑다운 2D 픽셀아트 생활형 농장 RPG를 지향한다. 핵심 재미는 작물 재배와 농장 확장이며, 목축업은 닭부터 시작한다. 첫 완성본은 농장과 작은 마을을 오가며 농사와 거래를 반복하는 작은 규모의 게임으로 만든다.

스타듀 밸리의 생활 순환 구조는 참고하되 캐릭터, 세계관, 그래픽, 작물, 건물과 세부 규칙은 독자적으로 설계한다.

## 현재 구현 상태

- Unity 6.6 기반 2D 프로젝트가 생성되어 있다.
- 게임은 1일 차 오전 6시에 시작한다.
- 현실 시간 7초마다 게임 시간 10분이 흐른다.
- 자정을 지나면 다음 날로 변경된다.
- 플레이 화면 오른쪽 위에 날짜와 시간이 표시된다.
- 시간 계산에 대한 EditMode 테스트 4개가 작성되어 있고 모두 통과했다.
- 시간 표시는 초기 검증용 UI이므로 정식 픽셀아트 UI 제작 시 교체해야 한다.

아직 플레이어, 저장된 게임 씬, 농장과 마을 맵, 농사, 닭, 인벤토리, 경제와 저장 기능은 구현되지 않았다.

현재 구현된 시간 속도는 초기 검증값이다. 현실 1분을 게임 5분으로 바꾸는 안은 기획 검토 중이며 아직 코드에 반영하지 않았다.

## 퀘스트와 도전 과제

퀘스트는 마을 광장의 게시판이나 게임 내 휴대폰을 통해 확인하는 방식으로 구성한다. 광장 게시판은 플레이어가 마을을 방문할 이유를 만들고, 휴대폰은 장소에 관계없이 편리하게 진행 상황을 확인할 수 있다는 장점이 있다. 둘 중 하나를 주된 수령 장소로 정할지, 게시판에서 수령하고 휴대폰에서 추적하는 혼합 방식을 사용할지는 추가 결정이 필요하다.

도전 과제는 일회성 퀘스트와 분리한다. 퀘스트는 보상과 이야기를 제공하는 단기 목표이고, 도전 과제는 누적 수확량, 농장 확장, 닭 사육과 같은 장기 기록을 다룬다. 첫 완성본에서는 농사와 닭에 직접 연결되는 소수의 도전 과제만 넣는 것이 좋다.

## 권장 핵심 게임 순환

첫 완성본의 하루는 다음 순서로 구성하는 것이 좋다.

1. 오전 6시에 농장 집에서 하루를 시작한다.
2. 밭을 갈고 밀 씨앗을 심고 물을 준다.
3. 닭에게 먹이를 주고 생산된 달걀을 수집한다.
4. 마을 상점에서 씨앗, 사료와 필요한 물품을 구매한다.
5. 수확물과 달걀을 판매 상자에 넣는다.
6. 하루를 마치면 판매 금액이 정산되고 작물과 닭의 상태가 갱신된다.
7. 번 돈으로 밭, 도구와 닭장을 확장한다.

시간 외의 수면, 판매 정산, 작물 성장과 닭 생산 규칙은 아직 기획 제안이며 확정되거나 구현되지 않았다.

## 첫 완성본에 필요한 시스템

### 필수 시스템

1. **플레이어 조작**: 4방향 이동, 충돌, 상호작용과 간단한 애니메이션
2. **월드**: 농장 맵, 작은 마을 맵, 건물 출입과 맵 전환
3. **농사**: 땅 갈기, 씨앗 심기, 물 주기, 날짜별 성장과 수확
4. **아이템**: 아이템 데이터, 인벤토리, 단축 슬롯과 아이템 획득·소비
5. **경제**: 돈, 상점 구매, 판매 상자와 가격 데이터
6. **닭 사육**: 닭장, 닭 구매, 먹이, 상태와 달걀 생산
7. **하루 진행**: 취침, 다음 날 처리와 하루 종료 정산
8. **저장과 불러오기**: 휴대폰 수동 저장, 취침 자동 저장, 플레이어 위치, 날짜, 돈, 농장 상태, 인벤토리와 닭 상태 저장
9. **퀘스트**: 퀘스트 데이터, 수락, 조건 추적, 완료와 보상
10. **도전 과제**: 누적 기록, 달성 조건, 보상 또는 배지
11. **UI**: 시간, 돈, 단축 슬롯, 상점, 인벤토리, 휴대폰, 퀘스트와 상호작용 안내

### 나중에 추가할 기능

- 계절과 날씨
- 여러 종류의 가축
- 낚시, 광산과 전투
- 주민 호감도와 이야기
- 축제
- 요리와 제작

이 기능들은 첫 농사·닭 순환이 재미있고 안정적으로 완성된 뒤 추가한다.

## 권장 기술 구조

게임 규칙과 Unity 화면 코드를 분리한다. 작물 성장, 날짜 계산, 가격, 닭 상태 같은 규칙은 가능한 한 일반 C# 코드로 작성하고, MonoBehaviour는 입력·씬·애니메이션·화면 표시를 연결하는 역할만 담당한다.

데이터는 ScriptableObject로 관리하는 것이 좋다. 작물, 씨앗, 도구, 아이템, 닭과 상점 상품을 코드에 직접 작성하지 않고 데이터 에셋으로 만들면 콘텐츠를 추가할 때 코드를 계속 수정하지 않아도 된다.

기능 영역은 `Time`, `World`, `Player`, `Farming`, `Inventory`, `Economy`, `Animals`, `Quest`, `Achievement`, `Save`로 나눈다. 각 영역은 다른 기능의 내부 구현에 직접 의존하지 않고 공개된 이벤트나 서비스만 사용하도록 한다.

퀘스트와 도전 과제는 동일한 조건 추적 기반을 공유할 수 있다. 예를 들어 `밀 10개 수확`, `달걀 5개 수집` 같은 게임 이벤트를 한 곳에서 발행하고, 퀘스트와 도전 과제가 각각 구독하도록 구성하면 중복 계산을 줄일 수 있다. 저장 시스템은 모든 기능의 상태를 직접 알기보다 각 영역이 제공하는 저장 데이터를 모아 기록하는 역할만 담당한다.

## 보완하거나 결정해야 할 점

### 우선 결정이 필요한 항목

- **목표 플랫폼**: PC만 지원할지, 모바일과 게임패드까지 고려할지
- **조작 방식**: 키보드·마우스 중심인지 게임패드도 첫 버전에 포함할지
- **픽셀 규격**: 16×16, 24×24 또는 32×32 타일 중 어떤 크기를 사용할지
- **화면 해상도**: 기준 해상도와 픽셀 퍼펙트 카메라 설정
- **시간 속도**: 현실 1분당 게임 5분 안을 유지할지 플레이 테스트 후 조정할지
- **하루 종료 규칙**: 취침 시각, 강제 종료 시각과 시간 정지 조건
- **저장 슬롯**: 한 개만 사용할지 여러 개를 지원할지
- **퀘스트 접근 방식**: 광장 게시판과 휴대폰의 역할을 어떻게 나눌지
- **도전 과제 보상**: 배지만 줄지, 돈이나 아이템도 함께 줄지
- **닭의 실패 규칙**: 먹이를 주지 않았을 때의 결과는 추가 논의 필요

현실 1분당 게임 5분이면 게임의 24시간은 현실 4시간 48분이다. 오전 6시부터 밤 10시까지도 현실 3시간 12분이 걸리므로, 일반적인 짧은 하루 반복보다 매우 느긋한 플레이에 적합하다. 시간 제한의 압박을 줄이는 것이 목표라면 사용할 수 있지만, 작물 성장과 취침 반복이 핵심이라면 하루가 지나치게 길게 느껴질 수 있다. 실제 맵과 농사 순환이 만들어진 뒤 5배, 20배와 현재 검증값을 비교해 결정하는 것이 좋다.

### 현재 구조에서 보완할 점

- 실제로 플레이할 저장된 씬이 없다.
- 시간 UI가 임시 `OnGUI` 방식이다.
- 시간 속도가 코드 기본값에 묶여 있어 추후 게임 설정 데이터로 분리해야 한다.
- 저장 시스템이 없으므로 시간과 날짜가 게임을 다시 시작할 때 초기화된다.

## 권장 개발 순서

1. 플레이어 이동과 픽셀 퍼펙트 카메라
2. 테스트용 농장 맵과 충돌
3. 상호작용과 도구 사용의 공통 구조
4. 밀 한 종류로 농사 전체 순환 완성
5. 인벤토리, 상점과 판매 상자
6. 하루 종료와 저장·불러오기
7. 닭 한 종류와 닭장 순환 완성
8. 퀘스트 조건 추적과 광장·휴대폰 UI
9. 농사와 닭 중심의 초기 도전 과제
10. 작은 마을과 정식 픽셀아트 UI
11. 작물·아이템 추가와 밸런스 조정

첫 목표는 많은 콘텐츠가 아니라 씨앗을 사고, 심고, 수확하고, 판매하여 다시 농장을 개선하는 한 번의 순환을 완성하는 것이다.
