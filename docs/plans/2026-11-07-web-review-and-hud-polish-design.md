# WebGL 검토와 HUD 정리 설계

## 목표

프로토타입을 브라우저 사이트로 실행해 피드백을 빠르게 반복한다. 첫 수정 범위는 캐릭터 이동의 멈칫거림, 상시 노출 안내창, 해상도에 따라 어긋나는 텍스트 배치다.

## 이동 표현

걷는 동안 대기 프레임을 섞지 않고 `1 → 2 → 3 → 2` 순서만 반복한다. 재생 속도는 초당 6프레임, 이동 속도는 초당 2.8 유닛으로 낮춘다. 충돌 영역은 몸 전체가 아니라 발 주변에 작게 배치해 건물과 나무 모서리에서 덜 걸리게 한다.

## 안내와 메시지

대화창은 항상 표시하지 않는다. `GameSession.MessageRevision`이 변경되면 새 메시지를 4초간 표시하고 자동으로 숨긴다. `E` 상호작용 안내는 가까운 대상이 있을 때만 별도 작은 배너로 표시한다. 기본 조작법은 화면에 상시 출력하지 않는다.

## 반응형 UI와 글꼴

HUD는 1280×720 가상 캔버스를 기준으로 배치한다. 실제 브라우저 크기에 맞춰 모든 패널과 텍스트를 같은 비율로 축소하고 남는 영역은 중앙 정렬한다. WebGL에서도 한글 글리프가 유지되도록 Noto Sans KR을 빌드에 포함한다.

## WebGL 검토 환경

Unity `BuildPipeline`으로 `Builds/WebGL`을 생성하고, 기본 페이지를 16:9 반응형 캔버스로 수정한다. 로컬 Node.js 서버는 gzip과 WebAssembly MIME 헤더를 제공한다. 주소는 `http://127.0.0.1:8765/`이며, 서버가 실행 중인 현재 컴퓨터에서만 접근할 수 있다.

## 검증

- EditMode 18개 테스트 통과
- Main 씬 PlayMode 테스트 통과
- WebGL 빌드 성공
- HTML 200 응답과 `.wasm.gz`의 `application/wasm`, `Content-Encoding: gzip` 확인
